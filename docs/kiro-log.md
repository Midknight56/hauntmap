# Kiro log

Copy this file to `docs/kiro-log.md` in the HauntMap repository (only if that file does not exist yet). One row per completed task, appended the same day by the agent that did the task. Crew rows name the agent (`parser`, `graph`, `fixtures`, `renderer`) in the Surface column; rows for fleet work name the fleet agent, never Kiro; Kiro's reviews of `investigation-ui` and `intake` tasks are labelled `review`, not implementation; one-line requests to another owner are rows too (`request to <owner>: <change>`), as are the gate package rows. `kiro-integration` rows use the task cell `kiro-integration, task <n> (<label>)`, where the label is one of `Setup: hook observation verify-on-stop`, `Setup: hook observation analyze-live`, `Setup: MCP registration`, `H9 session`, or absent; the `typecheck-on-save` observation, which belongs to no spec task, uses the task cell `Setup: hook observation typecheck-on-save`. The builder checks the Credits column against the Kiro usage display at the Wednesday and Saturday ledger updates. Write `none` when nothing failed; never invent a failure, a measurement or a result. Every row has seven cells (`tests/kiro/kiro-log.test.ts` parses the table and fails on a date cell starting with `EXAMPLE` or a commit cell equal to `0000000`). Worked examples of rows are in `kiro/hauntmap/kiro-log-examples.md` in the planning workspace, which is never copied into the repository.
