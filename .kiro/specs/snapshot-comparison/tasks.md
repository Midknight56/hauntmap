# Implementation Plan

Kiro does every task, alone, in the main checkout, on one branch `snapshot-comparison`, under `.kiro/steering/revision-2026-11-16.md`, which wins over this file where they differ: no worktrees, no integrator (where an older text says "Integrator:", Kiro does that step itself, subject to the gate below), no Crew renderer agent, no outside reviewer, every date in a title or in a text is history and not a deadline. The branch is merged into `main` only when `pnpm verify` and `pnpm verify:e2e` pass on it. Order of the specs: `analysis-core`, `kiro-integration` 1a to 8 and `investigation-ui` 1a to 13 and 15 are on `main` before task 1a starts; this spec then does tasks 1a to 4b, 8 to 12, 14 and 15; `kiro-integration` tasks 9 to 12, 14 and 15 start only after task 10 of this spec has `registerCompare` on `main`. Tasks 5, 6, 7 and 13 (the export feature) are not done; `intake` is not built; nothing here depends on either.

What is built and what is not. Comparison works for the bundled pair (`public/demo/manor/before` against `public/demo/manor/after`) and for the live snapshot (`public/demo/live.json`, handed over by `kiro-integration` through the `compare` handoff). Comparison of two folders or two GitHub refs chosen by the user is not built: the panel has no button for it, there is no `intake` handoff, no `COMPARE_INTAKE_ENABLED` flag and no request R3. The export dialog, the HTML and Markdown reports and the graph JSON are not built (tasks 5, 6, 7, 13). Audit of 2026-11-16 for skipping them: no file of `kiro-integration` imports from or refers to `src/features/export` (its requirement 4.4 and its design already read `compareStore.getState().result` through the development hook); the references to export in `investigation-ui` (introduction, 6.6 and 10.7 of its requirements; the architecture diagram, the development-hook paragraph, the feature-boundary row and the out-of-scope list of its design; tasks 2b and 12) were reworded the same day so that the `export` slot stays an empty registry slot that only a test stub fills, and no file of that spec names `src/features/export` or this spec's export requirements.

Gate for files of other specs. `.kiro/steering/ownership.md` gives this spec only `src/analysis/graph/compare.ts`, `src/features/compare/**`, `src/scene/compare/**` and `tests/compare/**`. Four changes in other specs' files are unavoidable; each is written once, in the task that names it, and runs only when `ownership.md` lists it as an exception for `snapshot-comparison`; otherwise the task stops at that step and says so in its log row (Kiro never edits `ownership.md`; the owner adds the exception). G1 `playwright.config.ts` (task 1c): the `dev` project matches `tests/compare/e2e/**` (it may already, read in 1a). G2 `src/components/App.tsx` and `src/components/MapView.tsx` (task 10): `MapView` takes an optional prop `comparison: { get(): unknown; subscribe(listener: () => void): () => void }`, puts `comparison: get()` into every `setStyleState` call and calls it again on every notification; `App.tsx` builds the compare store, passes that prop, calls `registerCompare`, installs `compareStore` and `compareWith` on the development hook and reads no scene handle. G3 `src/scene/styles.ts`, `src/scene/adapter.ts` and `src/styles/tokens.css` (task 9): the three tokens in `TOKENS` and in the CSS together (the fleet's `tests/ui/styles.test.ts` compares them), the optional `outlineStyle` field and the completion of the three `comparison-*` entries of `STATE_STYLES` that `investigation-ui` task 5 created, `SceneHandle.setStyleState` passing `state.comparison` to `applyComparison` of `src/scene/compare` (an absent `comparison` key keeps the last value, `null` clears it), `states` in `SceneDebug`, and `hitTest` skipping elements whose comparison state is `hidden`. G4 `src/components/Inspector.tsx` (task 8, only if the ghost-selection test shows that the inspector throws for an ID absent from the shown snapshot): the heading `<id>` and the line `Not in the shown snapshot. See the Comparison panel.` instead of a throw. Everything else in this spec reads the fleet's files and never writes them.

Environment: Windows, PowerShell, Kiro CLI 3.3.0, no person at the keyboard. Verify lines use PowerShell forms: `;` with a `$LASTEXITCODE` check instead of `&&`, `Select-String` instead of `grep`, `Measure-Command` instead of `time`, `$env:NAME = "1"` instead of an inline variable. Browser tests run headless only. Where a task wants a screenshot, a headless Playwright run writes the file when `$env:HAUNTMAP_SHOTS = "1"` (the fleet's `shot` helper); where a step needs a person or the named laptop it is marked `left for the owner` and is not done. Cases that need WebGL are skipped with the reason `no WebGL in headless Chromium` if headless Chromium has none, and the skip is named in the log row. Write every file as UTF-8 without a byte order mark and with LF line endings. Never run `git commit` unless the owner asks, so there is no commit trailer.

A task is done only after `pnpm verify` and, where named, `pnpm verify:e2e` pass on the branch, and its row is in `docs/kiro-log.md` the same day with the credits used (date, surface and model, `snapshot-comparison/<n>`, files, verify command and result, credits, what changed because of a failure or `none`). A task writes its own tests; there is no up-front file of failing tests, so `pnpm verify` stays green after every task. Two repair passes against the same observed defect, then stop, keep the reproducer and report it in the log. Never weaken a test to make it pass. There is no credit cap in this plan beyond the owner's. Every *verify* mark is settled by task 1a (or the task that names it) and the observed value is written into the file that carries the mark.
