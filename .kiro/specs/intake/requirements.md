# Requirements Document

## Introduction

`intake` is the pair of routes by which a judge or developer brings their own code into HauntMap: local folder analysis (a directory input, an exclusion review before any file content is read, reading in a worker with real progress and a cancel control, the 1,000-file and 25 MiB caps as errors rather than partial results, a coverage summary, `Save investigation on this device` and graph-file import) in `src/features/import`, and loading a public GitHub repository by URL through the jsDelivr GitHub mirror (the URL grammar, the listing with the include rules applied before any file request, the 400-file cap, at most six requests in flight, progress and cancel, the privacy note before the first request) in `src/features/github`. Both dialogs also run in "after" mode as the newer snapshot of a comparison through the `intake` handoff. It serves the judge who confirms on a folder or repository of their own that the analysis is real, and the developer investigating a project they work on. It implements "Local source analysis", "Public GitHub repository by URL", the intake parts of "Storage and privacy", work packages H10 and H13, matrix rows 19 (local and GitHub portion), 21, 22 and 30 of `plans/hauntmap-implementation-plan.md` (revision 3, 2026-11-03), on top of the `SourceSet`, `AnalysisOptions` and `Investigation` contracts of `analysis-core`, the fleet store, registry (`intake` handoff overload) and `Landing.tsx` of `investigation-ui`, `src/contracts/validate.ts` (`kiro-integration` task 4a) and request R3 of `snapshot-comparison`. Owner: fleet (non-Kiro agents), two worktrees (`../HauntMap-import` on `fleet/import`, `../HauntMap-github` on `fleet/github`), reviewed by Kiro per merged task from the 250-credit review line shared with `investigation-ui`. Implementation November 10–18 (gate November 18), fixes to the November 27 freeze.

Terms used below. **Included file**: a file whose extension is in `AnalysisOptions.includeExtensions`, whose path has no segment in `excludeDirectories`, whose basename matches no pattern in `excludeFilePatterns`, whose size is at most `maxFileBytes` (1,048,576) and whose first 8,192 bytes contain no NUL byte (the last condition is known only when the file is read). **Review**: the screen of the local dialog that lists included and skipped files before `Analyze`. **Root label**: `Investigation.sourceLabel`, `local:<folder name>` or `gh:<owner>/<repo>@<ref>`. **Analysis client**: `src/workers/client.ts` as `analyze(sourceSet: SourceSet, options: AnalysisOptions): Promise<Investigation>` (the shape `investigation-ui` task 1a records). **Read worker**: `src/features/import/readFiles.worker.ts`, this spec's own worker that reads `File` objects. **Listing**: the jsDelivr response for `https://data.jsdelivr.com/v1/package/gh/{owner}/{repo}@{ref}/flat`. **In flight**: a file request sent and not yet settled. **Mode**: `open` (the dialog opens the result in the fleet store) or `after` (the dialog resolves the result to the caller and touches no investigation). **Status region**: the one `role="status"` element written through `store.actions.setStatus`. **Development build**: a build in which `window.__hauntmap` exists (`investigation-ui` Testing Strategy). **Named laptop**: the machine named in `docs/performance.md` on November 4. Sizes are shown as `<n> KB` (1,024 bytes, rounded up) below 1 MiB and `<n.n> MiB` from 1 MiB.

## Requirements

### Requirement 1 — Registration, the two dialogs and the two modes

**User Story:** As the landing screen and the comparison panel, I want one `intake` handoff that opens the right dialog in the right mode and resolves a typed result, so that the intake flows plug into the app without the fleet shell or the comparison feature knowing their internals.

#### Acceptance Criteria

1. THE SYSTEM SHALL register, at app start from `src/features/import/register.ts` (`registerIntake(deps)`, called by `src/components/App.tsx` through the integrator), one `intake` handoff through `registry.registerHandoff("intake", fn)` whose `kinds` property lists `"local"` always and `"github"` when the GitHub feature is wired (`registerIntake({ github: githubOpener })`); `tests/intake/register.test.ts` asserts the `kinds` list for both wirings.
2. WHEN the handoff is called with `{ purpose, kind: "local" }` THEN THE SYSTEM SHALL open the dialog `<section role="dialog" aria-modal="true" aria-labelledby>` headed `Analyze a local folder`, and with `kind: "github"` the dialog headed `Load a GitHub repository`; in `after` mode the heading SHALL read `Analyze a local folder as the newer snapshot` or `Load a GitHub repository as the newer snapshot`; focus SHALL move to the dialog's first control, Tab and Shift+Tab SHALL stay inside the dialog, and Escape or `Close` SHALL close it, resolve `{ ok: false, reason: "cancelled" }` and return focus to the element that was focused before the call.
3. WHEN a dialog produces an investigation in `open` mode THEN THE SYSTEM SHALL call `store.actions.openInvestigation(investigation, sourceText, { demo: false })`, close the dialog, return focus to the opener, show the summary message of 3.5, 6.3 or 8.5 in the status region, and resolve `{ ok: true, investigation, sourceText, label }`; in `after` mode THE SYSTEM SHALL call no store action other than `setStatus` (and that only for the summary message), close the dialog and resolve the same result (`tests/intake/after-mode.test.tsx` asserts that `openInvestigation`, `restart`, `select` and `setPreset` are never called in `after` mode).
4. WHEN the handoff is called while a dialog is open THEN THE SYSTEM SHALL return the pending promise of the open dialog and open nothing.
5. THE SYSTEM SHALL write every message of this spec through `store.actions.setStatus` (the one status region, `investigation-ui` 10.2) and SHALL show progress as visible text inside the dialog with `aria-busy="true"` on the dialog while work runs; the status region receives one message at the start of reading or fetching and one at completion, cancellation or failure, never per tick.
6. THE SYSTEM SHALL render every folder name, path, specifier, label, URL and message as a React text node: no `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML` in `src/features/import/**` or `src/features/github/**` (`tests/intake/no-html-injection.test.ts`); a chosen folder named `a&b<img>` SHALL appear verbatim in the review and `document.querySelector("img")` SHALL be null.
7. WHILE the renderer is unavailable (`investigation-ui` 12.1) THE SYSTEM SHALL keep both dialogs fully working; they never call the scene.

### Requirement 2 — Local folder: selection and the exclusion review before any content is read

**User Story:** As a developer choosing a folder, I want to see what will be read and what will be skipped before any file content is touched, so that I know exactly which files the analysis covers and that nothing outside them is opened.

#### Acceptance Criteria

1. THE SYSTEM SHALL offer `<input type="file" webkitdirectory>` labelled `Choose a folder` as the first control of the local dialog; IF `webkitdirectory` is not a property of a freshly created `<input type="file">` THEN THE SYSTEM SHALL render no folder input, show the text `Folder selection is not available in this browser. Import a graph file instead.`, and keep the graph-file section of Requirement 6 as the first control.
2. WHEN files are chosen THEN THE SYSTEM SHALL classify them from `File.webkitRelativePath`, `File.name` and `File.size` only; `File.text()`, `arrayBuffer()`, `stream()` and `slice()` SHALL not be called before `Analyze` is activated (`tests/intake/review.test.ts` passes `File`-like objects whose read methods throw); the first path segment (the chosen folder's name) is removed so that paths are relative to the root with forward slashes and no leading `./`, and the root label is `local:<folder name>`.
3. THE SYSTEM SHALL classify with the same rules and order as the Node loader of `kiro-integration` 2.2, reading them from `DEFAULT_ANALYSIS_OPTIONS` of `src/contracts/` and never copying the values: a path with a segment in `excludeDirectories` → one `skipped` entry `{ path: "<dir>/", reason: "excluded-dir" }` per excluded directory path (its files are not listed individually); a basename matching an `excludeFilePatterns` glob → `secret-pattern`; an extension not in `includeExtensions` → `extension`; `size > maxFileBytes` → `oversized`; otherwise included (the `binary` reason is decided at read time, 3.1).
4. WHEN the classification is done THEN THE SYSTEM SHALL show the review: `Folder: <name>`; `Included: <n> files, <size>`; `Skipped: <k>` followed by the lines `<a> in excluded directories (.git, node_modules, dist, build, out, .next, coverage)`, `<b> secret or environment files`, `<c> other file types`, `<d> over 1 MiB` (a line is omitted when its count is 0); the lists `Included files (<n>)` and `Skipped files (<k>)` sorted in code-unit order, each showing its first 200 entries with `… and <m> more` when longer, a skipped entry carrying its reason as `<path> · <reason>`; the sentence `Included files are read in this browser and kept in memory.`; and the buttons `Analyze`, `Back` (returns to the folder input) and `Close`.
5. IF the included count exceeds 1,000 THEN `Analyze` SHALL be rendered `aria-disabled="true"` with the text `This folder has <n> included files; the limit is 1,000. Choose a subfolder.`; IF the sum of included sizes exceeds 26,214,400 bytes THEN likewise with `This folder has <size> of included text; the limit is 25 MiB. Choose a subfolder.`; IF the included count is 0 THEN likewise with `No JavaScript or TypeScript files were found in <folder> (<k> files skipped).`; THE SYSTEM SHALL never analyze a subset of the included files (the plan's rule: caps are errors, not partial results).
6. WHEN `tests/intake/fixtures/folder` is chosen (materialized as `sample-local/`: `src/a.ts`, `src/b.ts`, `src/c.tsx`, `bin.ts`, `big.ts`, `README.md`, `.env`, `secret.pem`, `node_modules/pkg/index.js`, `dist/out.js`) THEN the review SHALL show `Included: 4 files` (`bin.ts`, `src/a.ts`, `src/b.ts`, `src/c.tsx`; `bin.ts` is excluded only at read time) and `Skipped: 6` with `2 in excluded directories (…)`, `2 secret or environment files`, `1 other file types`, `1 over 1 MiB`, and `Skipped files (6)` listing `.env · secret-pattern`, `README.md · extension`, `big.ts · oversized`, `dist/ · excluded-dir`, `node_modules/ · excluded-dir`, `secret.pem · secret-pattern`.

### Requirement 3 — Local folder: reading in a worker, progress, cancel, analysis and the coverage summary

**User Story:** As a developer analyzing a large folder, I want reading and parsing to happen off the main thread with real progress and a cancel that leaves my previous investigation intact, so that the dialog never freezes and a wrong selection costs nothing.

#### Acceptance Criteria

1. WHEN `Analyze` is activated THEN THE SYSTEM SHALL post the included `File` objects to the read worker as one request `{ requestId, kind: "read", files }`; the worker SHALL read each file with `file.text()` (UTF-8; a leading byte-order mark is removed, as `Blob.text()` removes it, matching `kiro-integration` 2.3), probe the first `min(size, 8192)` bytes for a NUL byte and skip such a file with reason `binary`, set `bytes` to `File.size`, post `{ requestId, kind: "progress", done, total }` at most every 100 ms, and post `{ requestId, kind: "done", sourceSet }` with `files` sorted by path in code-unit order and `rootLabel` `local:<folder name>`.
2. WHILE reading runs THE SYSTEM SHALL show `Reading <done> of <total> files` in the dialog, then `Analyzing <n> files…` while the analysis client runs, with `Cancel` enabled throughout and every other control `aria-disabled="true"`.
3. WHEN `Cancel` is activated during reading THEN THE SYSTEM SHALL call `terminate()` on the read worker and create a fresh one (a message cannot interrupt a running read); during analysis THEN THE SYSTEM SHALL cancel the analysis client's request (the fleet client's terminate-and-recreate, `analysis-core`); in both cases THE SYSTEM SHALL leave `ViewState.investigation`, `selection`, `routeFilter`, `camera`, `expandedWings` and `layout` deep-equal to their values before `Analyze`, show `Analysis cancelled. <label> is still open.` (or `Analysis cancelled.` when no investigation is open), and return the dialog to the review with `Analyze` enabled (`tests/intake/e2e/local.spec.ts` cancels mid-read on a generated 400-file folder and asserts the state through the development hook).
4. WHEN reading completes THEN THE SYSTEM SHALL call `analysisClient.analyze(sourceSet, { ...DEFAULT_ANALYSIS_OPTIONS, preset: store.getState().preset })`, build `sourceText = new Map(sourceSet.files.map(f => [f.path, f.text]))`, and proceed per 1.3; the investigation's `sourceLabel` SHALL be `local:<folder name>`.
5. WHEN the analysis resolves THEN THE SYSTEM SHALL show, in the status region and on the dialog's result screen, `Analyzed <folder>: <m> modules, <r> relations, <d> diagnostics; <k> files skipped before reading, <b> binary files skipped, <f> files failed to parse.` where `<r>` counts distinct relation IDs and `<f>` counts modules with `parseStatus: "failed"`; for the fixture of 2.6 the message SHALL be `Analyzed sample-local: 3 modules, 1 relations, 0 diagnostics; 6 files skipped before reading, 1 binary files skipped, 0 files failed to parse.`
6. IF the read worker posts an error, or the analysis client rejects, times out or is terminated by a supersession THEN THE SYSTEM SHALL show `The folder could not be analyzed (<message>). The previous investigation is unchanged.` (in `after` mode the message is `The folder could not be analyzed (<message>).` and the result is `{ ok: false, reason: "failed", message }`), preserve the state of 3.3, and return the dialog to the review.
7. THE SYSTEM SHALL open the map within 3,000 ms after reading completes for a 200-file, 2 MiB generated folder on the named laptop (the plan's parse-and-layout target; the parser's share is `analysis-core`'s and the layout's share is `investigation-ui` 3.8); the figure is recorded in the task 4 log row with the device and is a target until recorded.

### Requirement 4 — Privacy of local analysis (matrix row 30)

**User Story:** As a developer analyzing private code, I want proof that the local flow sends nothing about my folder anywhere, so that the write-up's statement about local analysis rests on a recorded check and not on a promise.

#### Acceptance Criteria

1. THE SYSTEM SHALL make no network request as part of the local flow: `tests/intake/e2e/local.spec.ts` records every request from the moment the folder is chosen until the map is open and asserts that each request URL is under the app base and ends in a static asset extension of the build (`.js`, `.css`, `.woff2`, `.png`, `.svg`, `.json` under `assets/`), and that no request URL, header or body contains the folder name `sample-local`, any fixture path or the content sentinel `SENTINEL-LOCAL-4e2b17` that `src/a.ts` of the fixture carries (row 30, automated portion).
2. THE SYSTEM SHALL have the reviewer agent repeat the check by hand on the named laptop with the browser's network panel open across the whole local flow (choose, review, analyze, open, search, inspect), saving `docs/acceptance/img/2026-11-18-network-local.png` and a row in `docs/acceptance/2026-11-18-gate.md` (row 30, recorded portion); only after that row exists may the landing sentence of `investigation-ui` 1.2 be strengthened and the write-up say that local analysis sends no code anywhere; static asset requests are ordinary website requests and are named as such.
3. THE SYSTEM SHALL keep source text in the store's in-memory map only; the local flow SHALL write nothing to `localStorage`, `sessionStorage` or IndexedDB except through the explicit save of Requirement 5 (`tests/intake/local-intake.test.tsx` spies on the three storages).
4. THE SYSTEM SHALL log no folder name, path, specifier or content to the console or to any endpoint; a failure logs the error name and stack only (`tests/intake/local-intake.test.tsx` spies on `console.error`; no telemetry exists in this build).
5. THE SYSTEM SHALL pass file text to the analysis client as data only; it SHALL never execute, `import()`, evaluate or render as active content any chosen file, and SHALL never fetch an import a chosen file names (`tests/intake/no-execution.test.ts` chooses a folder whose `postinstall.js` and `index.html` would write a marker if executed or rendered, and asserts the marker is absent and no request was made).

### Requirement 5 — Save investigation on this device

**User Story:** As a developer who analyzes the same folder repeatedly, I want to save an investigation on my own machine by an explicit action, with source text included only when I say so, so that nothing is persisted by accident and the saved copy can be forgotten.

#### Acceptance Criteria

1. WHEN a local analysis has completed in `open` mode THEN the dialog's result screen SHALL offer the button `Save investigation on this device`, the checkbox `Include source text` (unchecked on every display) and the sentence `Saved investigations stay in this browser's storage until you forget them.`; nothing is saved without the button (`tests/intake/saved.test.ts` asserts no write without it).
2. WHEN the button is activated THEN THE SYSTEM SHALL write one record to the IndexedDB database `hauntmap`, object store `investigations`, keyed by the root label: `{ savedVersion: 1, label, savedAt: <ISO 8601 UTC>, investigation, sourceText: <Record<path, text>> | null }` (`sourceText` non-null only with the checkbox checked), replacing a record with the same label, and show `Saved <label> on this device (<n> KB, source <included|omitted>).`
3. THE SYSTEM SHALL list, on the local dialog's first screen, `Saved on this device (<n>)` sorted by `savedAt` descending, each item `<label> · <m> modules · saved <YYYY-MM-DD> · source <included|omitted>` with the buttons `Open` and `Forget`; WHEN `Open` is activated THEN THE SYSTEM SHALL validate the record's investigation with `validateInvestigation` and proceed per 1.3 with the record's source map (or `null`), showing `Opened <label> from this device.`; IF validation fails THEN THE SYSTEM SHALL delete the record and show `The saved investigation <label> is not valid (<first error>) and was removed.`; WHEN `Forget` is activated THEN THE SYSTEM SHALL delete the record and show `Forgot <label>.`
4. IF IndexedDB is unavailable (`indexedDB` undefined, `open` throwing or its request erroring) THEN the save button SHALL be rendered `aria-disabled="true"` with the text `Saving is not available in this browser.` and the saved list SHALL be absent; IF a write fails (quota or any error) THEN THE SYSTEM SHALL show `The investigation could not be saved (<error name>).` and keep the dialog open.
5. THE SYSTEM SHALL keep saved records across `Restart demo` (`investigation-ui` 1.7 clears `localStorage` except the preferences and does not touch IndexedDB); only `Forget` removes a record; saved records never include labels, paths or text of any investigation other than the one saved.
6. THE SYSTEM SHALL implement the store behind the interface `SavedStore` of `design.md` with an injected adapter so that `tests/intake/saved.test.ts` runs against an in-memory fake (no new dependency) and the browser adapter is exercised once by `tests/intake/e2e/local.spec.ts` (save, reload the page, open, forget).

### Requirement 6 — Graph-file import

**User Story:** As a judge in a browser without directory selection, or a developer who exported a graph earlier, I want to open a graph JSON file directly, so that the investigation is reachable without re-analysis and the export format round-trips.

#### Acceptance Criteria

1. THE SYSTEM SHALL offer, on the local dialog's first screen, the section `Import a graph file` with `<input type="file" accept=".json,application/json">` labelled `Choose a graph file`; it SHALL accept a bare `Investigation` or the `GraphExport` envelope of `snapshot-comparison` 9.1 (the value under `investigation`, plus `source.files[<label>]` when present as the source map).
2. IF the file is larger than 26,214,400 bytes THEN THE SYSTEM SHALL show `The graph file is larger than 25 MiB.` without reading it; IF the text is not JSON THEN `The graph file is not JSON (<SyntaxError message>).`; IF `validateInvestigation` of `src/contracts/validate.ts` fails THEN `The graph file is not valid: <first error>.`; in every failure the dialog stays open and the state of 3.3 is preserved.
3. WHEN the file is valid THEN THE SYSTEM SHALL proceed per 1.3 with `sourceText` from the envelope's source map for the investigation's label when present and `null` otherwise (the inspector then shows the fleet's `Source not included in this snapshot; evidence is path, line and specifier.`), keep `investigation.sourceLabel` unchanged as the label, and show `Imported <label>: <m> modules, <r> relations (source <included|omitted>).`
4. WHEN `tests/intake/fixtures/graph/export-sample.json` (a `GraphExport` of the `triad`-shaped investigation with label `local:triad`, no source), `bare-investigation.json` (the same investigation bare), `export-with-source.json` (the envelope with `source.files["local:triad"]`), `malformed.json` (`schemaVersion: 2`) and `not-json.txt` are imported THEN the first three SHALL open with the messages `Imported local:triad: 4 modules, 3 relations (source omitted)` (twice) and `(source included)`, and the last two SHALL show `The graph file is not valid: schemaVersion must be 1 (found 2).` and `The graph file is not JSON (<SyntaxError message>).` (prefix matched).

### Requirement 7 — GitHub: URL, privacy note, listing and the include rules

**User Story:** As a judge, I want to paste a public repository URL and have the listing filtered by the same rules as a local folder before a single file is fetched, with a plain statement of what leaves my browser, so that the GitHub route is as predictable as the local one.

#### Acceptance Criteria

1. THE SYSTEM SHALL offer, in this DOM and Tab order: the text field `Repository URL`, the field `Branch or tag` (rendered only per 7.3), the button `Load` and `Close`; the privacy note `Repository name and file paths are requested from the jsDelivr CDN; local folder analysis still sends nothing.` SHALL be visible as text above `Load` from the dialog's first render, before any request (matrix row 21).
2. THE SYSTEM SHALL accept `https://github.com/{owner}/{repo}` with an optional trailing `/` or `.git`, and an optional `/tree/{ref}` where `owner`, `repo` and `ref` match `[A-Za-z0-9_.-]+` (`parseGithubUrl` of `src/features/github/url.ts`, pure); a path after `/tree/{ref}`, or any other path after the repository, SHALL be rejected with `Subfolders are not supported yet; paste the repository root.`; a `ref` containing `/` cannot be told from a subpath and SHALL be rejected the same way while the `Branch or tag` field is shown so the ref can be typed there; any other string SHALL be rejected with `Enter a URL of the form https://github.com/owner/repo or https://github.com/owner/repo/tree/branch.`; rejection makes no request.
3. WHEN no ref is given THEN THE SYSTEM SHALL request the listing without `@{ref}` (`https://data.jsdelivr.com/v1/package/gh/{owner}/{repo}/flat`), which selects the default branch (*verify* on November 14 that omitting the version selects the default branch, that the listing endpoint accepts branch names as `{ref}`, and how long it caches a branch ref); IF omitting the version does not select the default branch THEN THE SYSTEM SHALL show the `Branch or tag` field pre-filled with `main`; IF the endpoint serves only tags and commits THEN THE SYSTEM SHALL resolve the branch to a commit first (*verify* the endpoint) and show the resolved commit (first 7 hex characters) in the result line; the outcome of the *verify* and the chosen path are written into `docs/limitations.md`.
4. WHEN `Load` is activated with a valid URL THEN THE SYSTEM SHALL request the listing with `credentials: "omit"` and no header beyond the browser defaults, read from each entry its path and size (*verify* the field names on the live response on November 14; the parser reads only those two and the fixture `tests/intake/fixtures/gh/listing-small.json` copies the observed shape), remove a leading `/` from each path (*verify*), and apply the classification of 2.3 to the listing with the listed size standing in for `File.size` (the `binary` probe runs on the fetched body).
5. IF the included count exceeds 400 THEN THE SYSTEM SHALL fetch no file and show `<owner>/<repo>@<ref> has <n> included files; the limit is 400. First excluded: <path>.` where `<path>` is the 401st included path in code-unit order (the generated listing `listing-over-cap.json` of 401 entries `src/m<i>.ts` yields `src/m99.ts`; the test derives it from the sorted list); IF the included count is 0 THEN `No JavaScript or TypeScript files were found in <owner>/<repo>@<ref>.` (matrix row 22, cap portion).
6. IF the listing response status is not 200, or the request rejects THEN THE SYSTEM SHALL show `Could not list <owner>/<repo>@<ref>: <status or error name>. Only public repositories are supported.`, fetch nothing and preserve the state of 3.3 (matrix row 22; a private or missing repository and a missing ref take this path with whatever status jsDelivr returns, *verify* on November 14 and record the observed statuses in `docs/limitations.md`).
7. THE SYSTEM SHALL use the root label `gh:<owner>/<repo>@<ref>` with `<ref>` as entered or typed, and `default` when no ref was given and the listing does not report the resolved ref (*verify* whether it does); the dialog's result line SHALL show `Loaded <n> files from <owner>/<repo>@<ref>` plus ` (commit <7 hex>)` when a commit was resolved.

### Requirement 8 — GitHub: fetching with bounded concurrency, progress, cancel, caps and the result

**User Story:** As a judge on broadband, I want a 200-file repository on the map within ten seconds with visible progress and a cancel that aborts in-flight requests, so that the GitHub route is usable live.

#### Acceptance Criteria

1. THE SYSTEM SHALL fetch each included file from `https://cdn.jsdelivr.net/gh/{owner}/{repo}@{ref}/{path}` with `credentials: "omit"`, at most 6 requests in flight at any moment, one `AbortController` for the whole batch (`tests/intake/jsdelivr.test.ts` with a fake `fetch` asserts the pending count never exceeds 6 and that the number of file requests equals the included count; P4).
2. WHILE files are fetched THE SYSTEM SHALL show `<done> of <total> files` in the dialog, updated per settled file, then `Analyzing <n> files…`; `Cancel` SHALL be enabled throughout and the other controls `aria-disabled="true"`.
3. WHEN `Cancel` is activated THEN THE SYSTEM SHALL abort the controller (in-flight requests reject with `AbortError`), discard every received body, preserve the state of 3.3, show `Loading cancelled. <label> is still open.` (or `Loading cancelled.`) and return the dialog to the URL field (`tests/intake/e2e/github.spec.ts` cancels at 50 of 200 routed files and asserts that no request is issued afterwards; matrix row 22, cancel portion).
4. IF a file response status is not 200, or a file request rejects for a reason other than abort THEN THE SYSTEM SHALL abort the rest and show `Could not fetch <path> from <owner>/<repo>@<ref> (<status or error name>). Nothing was loaded.` with the state of 3.3 preserved; a body whose first 8,192 bytes contain a NUL byte SHALL be skipped with reason `binary`; a file whose listed size exceeds 1,048,576 is skipped as `oversized` without being fetched (7.4).
5. WHEN the last file has arrived THEN THE SYSTEM SHALL build the `SourceSet` (`rootLabel` the label of 7.7, `files` sorted by path, `bytes` = the body's byte length), call `analysisClient.analyze(sourceSet, { ...DEFAULT_ANALYSIS_OPTIONS, preset: store.getState().preset, maxFiles: 400 })`, build the source map, proceed per 1.3 and show `Loaded <owner>/<repo>@<ref>: <n> files, <m> modules, <r> relations, <d> diagnostics.`; the recorded `options.maxFiles` of 400 is what distinguishes a GitHub snapshot from a local one in a comparison's options note.
6. THE SYSTEM SHALL reach the map within 10,000 ms of `Load` for a public repository of about 200 included files on the named laptop over broadband (matrix row 21): the repository is chosen by the intake writer and the builder on November 14 (plan open decision) and named in `docs/performance.md`; `tests/intake/e2e/github.spec.ts` runs the same flow against routed fixtures (no network) and asserts the sequence, and the builder's real-network run on the named laptop records the figure, the repository, the ref and the date under a `GitHub load` heading of `docs/performance.md`; the figure is a target until recorded.
7. WHEN `tests/intake/e2e/github.spec.ts` routes the listing to 404 and to 403 THEN both SHALL show the 7.6 message with that status and no file request SHALL be issued; WHEN it routes `listing-over-cap.json` THEN the 7.5 message SHALL appear with `src/m99.ts` and no file request; WHEN it routes `listing-small.json` and its bodies THEN the map SHALL open with `Loaded <owner>/<repo>@main: 3 files, 3 modules, 1 relations, 0 diagnostics.`
8. THE SYSTEM SHALL send the repository name, ref and file paths to jsDelivr and nothing else: no cookie, no custom header, no query parameter beyond the URL forms above (`tests/intake/jsdelivr.test.ts` inspects every request the fake `fetch` receives).

### Requirement 9 — The `intake` handoff in `after` mode (`snapshot-comparison` request R3)

**User Story:** As the comparison feature, I want to ask for a second local folder or GitHub ref as the newer snapshot without the current investigation being replaced, so that `Local folder as the newer snapshot…` and `GitHub repository as the newer snapshot…` work through the same dialogs.

#### Acceptance Criteria

1. WHEN the handoff is called with `{ purpose: "after", kind }` THEN THE SYSTEM SHALL run the dialog of that kind with the heading suffix of 1.2 and, on success, resolve `{ ok: true, investigation, sourceText, label }` without calling `openInvestigation`; the summary message of 3.5 or 8.5 is still written to the status region.
2. WHEN the dialog is closed or cancelled THEN THE SYSTEM SHALL resolve `{ ok: false, reason: "cancelled" }`; WHEN a failure of 3.6, 6.2, 7.5, 7.6 or 8.4 occurs THEN THE SYSTEM SHALL resolve `{ ok: false, reason: "failed", message }` where `message` is the failure sentence without the trailing `The previous investigation is unchanged.` (the caller appends its own preservation sentence, `snapshot-comparison` 10.3), and SHALL write no status message for it (the caller does).
