# Implementation Plan

Fleet-owned spec, reviewed by Kiro. Window November 4–6 for task 0 (the H1 spike, gate November 6), November 5–18 for tasks 1a–12 (H4, the November 18 visual gate) and November 17–27 for tasks 13–15 (H7, the November 27 freeze). Each module is written in its own worktree (`../HauntMap-<module>`, branch `fleet/<module>` from `main`) by one agent; a worktree touches only the folders and files named in its task. Three files have one writer for the whole window: `src/components/Toolbar.tsx` and `src/components/App.tsx` belong to the shell worktree (task 6a) and `src/components/MapView.tsx` to the mapview worktree (tasks 6b and 7); the toolbar is written once with every control of 10.1 wired to store actions and registry slots, later tasks add components that `App.tsx` renders, and any change to those three files is a one-line request in the asking task's log row that the shell or mapview writer lands the same day. Merge order: task 6a merges by November 12, before tasks 7, 8, 10, 11 and 12 branch; task 2a before 2b, 6a and 6b; task 9 before 10 branches (the panel reuses the inspector's card layout). Wiring into `src/components/App.tsx` (rendering each landed component), `package.json` scripts, the Vitest and Playwright configuration, `.kiro/steering/ownership.md` and `src/workers/layout.worker.ts` goes through the integrator named in `.kiro/steering/ownership.md` on a one-line request in the task's log entry. Every task that touches `src/scene/**` (3, 4, 5) merges before November 18, when `src/scene/` passes to the Crew renderer agent; a scene defect found after that date is handed to the renderer agent through `docs/kiro-log.md`, not fixed by the fleet. Preconditions on `main`: `src/contracts/` with the plan's types, `src/workers/client.ts`, `src/analysis/graph` with cycles, trace and the preset filter (at least stubs that pass `pnpm verify`), `public/demo/manor/{before,after}` and `public/demo/annex` with `expected.json` (the manor pair from the November 4 scaffold), `docs/decisions.md` with the November 6 layout decision (task 0 writes it). A task is done only after `pnpm verify` and, where named, `pnpm verify:e2e` pass on its branch; the integrator merges only when both pass on the merge result, then requests the Kiro review of task 15 for that merge. `pnpm verify:e2e -- <file>` runs one spec in its Playwright project (*verify* that the script forwards the argument; otherwise run the Playwright binary with the file path and `--project`). Two repair passes against the same observed defect, then stop and hand the reproducer to the builder. Kiro review credits for this spec and `intake` together total at most 250 (the 220 rule of 12.7); implementation rows in `docs/kiro-log.md` name the fleet agent, never Kiro.
