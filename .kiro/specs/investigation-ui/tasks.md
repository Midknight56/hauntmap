# Implementation Plan

Kiro does every task, alone, in the main checkout, on one branch `investigation-ui`, under `.kiro/steering/revision-2026-11-16.md` (no worktrees, no integrator, no Crew agents, no outside reviewer; where an older text says "Integrator:", Kiro does that step itself; ignore every date). The branch is merged into `main` only when `pnpm verify` passes, and also `pnpm verify:e2e` from task 1c on. Not built: task 0 (the spike; the engine is dagre, no ELK), the performance part of task 14 (`pnpm perf:record`, `tests/e2e/performance.spec.ts`, `docs/performance.md` rows; they need a named laptop and a person, so they are left for the owner), and the whole `intake` spec (the landing screen shows only `Explore the manor` and `Explore the annex`; nothing here depends on intake). Browser tests run headless only; where a task wants a screenshot, a headless Playwright spec writes the file when `$env:HAUNTMAP_SHOTS = "1"`; where a step needs a person or a named laptop it is marked `left for the owner` and is not done. All commands are PowerShell commands; write every file as UTF-8 without a byte order mark and with LF line endings. Never run `git commit` unless the owner asks.

Execution order (the numbers are task names, not the order): 1a, 1c, 1b, 2a, 2b, 3, 4, 5, 6a, 6b, 9, 7, 8, 10, 11, 12, 13, 14, 15. Task 9 runs before 7 because search focuses the inspector heading and `Focus` is an inspector button. A task's tests are written inside that task, so `pnpm verify` is green after every task; there is no up-front file of failing tests. An e2e spec file is created by the first task that owns one of its cases, and each later task adds its own cases; a task's Verify line runs only the cases that task owns (`pnpm verify:e2e -- <file> -g "<case title>"`). Cases that need a scene (WebGL) are skipped with the reason `no WebGL in headless Chromium` if headless Chromium has none, and the skip is named in the log row; they are never run headed.

Ownership. `.kiro/steering/ownership.md` gives this spec `src/scene/**`, `src/features/investigation/**`, `src/features/samples/**`, `src/features/demo/**`, `src/components/**`, `src/styles/**`, `src/workers/layout.worker.ts`, `tests/ui/**` and `tests/e2e/**`. It gives the root configuration files (`package.json`, `tsconfig.json`, `vitest.config.ts`, `eslint.config.js`, `.gitignore`) to `analysis-core` and names no owner for `index.html`, `vite.config.ts` and `.env.devhook`; task 1c needs all of them. This spec reads `src/analysis/**`, `src/contracts/**`, `src/workers/client.ts`, `scripts/pack-samples.ts` and `public/demo/**` and never writes them. If a task needs another spec's folder, Kiro stops and says so. Facts on `main` as of 2026-11-16: `findCycles`, `trace`, `relationId`, `occurrenceId` come from `src/analysis/index.ts`; `includesRelation` and `presetRelations` come from `src/analysis/graph/presets.ts` (not re-exported from `index.ts`; a read-only deep import); the analysis client is `createAnalysisClient` in `src/workers/client.ts` with `analyze({ files, rootLabel, options }, onProgress?)`; there is no layout client; `public/demo/**/sources.json` is `{ files: [{ path, text }] }`; `expected.json` has `modules`, `wings` (keys without `src/`), `imports`, `diagnostics`, `cycles`, `receiptToCheckout`. A task is done only after `pnpm verify` passes (and `pnpm verify:e2e` where named). Two repair passes against the same observed defect, then stop and report the reproducer. Never weaken a test to make it pass. Each finished task gets one row in `docs/kiro-log.md` the same day, with the credits used.
