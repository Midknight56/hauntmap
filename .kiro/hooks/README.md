# HauntMap hooks

Three standalone hook files in `.kiro/hooks/`, and this README, which holds the files table, the *verify* ledger, the observation procedure and the rules. The hooks are command actions only: agent actions inject a prompt, cost credits and are not part of this repository. Kiro does every task in single Kiro CLI sessions, one spec at a time (`.kiro/steering/revision-2026-11-16.md`, which wins where this file differs). The hooks implement "Kiro integration as a product feature" of `plans/hauntmap-implementation-plan.md` (revision 3, 2026-11-03) and Requirement 6 of `.kiro/specs/kiro-integration/requirements.md`.

| File | Entries (`name`: fires on) | Matcher | Command | Timeout (s) | Task |
| --- | --- | --- | --- | --- | --- |
| `verify-on-stop.json` | `verify-on-stop`: agent stop (trigger `Stop`) | none | `pnpm verify`: typecheck, lint, the Vitest suites, `pnpm pack:samples --check` and `pnpm check:expected`; the 90 s figure is a target until a log row records `Measure-Command { pnpm verify }` | 600 | `kiro-integration` task 2 |
| `typecheck-on-save.json` | `typecheck-on-save`: file save (trigger `PostFileSave`) | `\.(ts\|tsx)$` | `pnpm typecheck` | 120 | none (observed once in the `analysis-core` session, row `Setup: hook observation typecheck-on-save`) |
| `analyze-live.json` | `analyze-live`: agent stop (`Stop`); `analyze-live-on-save`: file save (`PostFileSave`) | none; `^samples/manor/.*\.(js\|jsx\|ts\|tsx\|mjs\|mts)$` | `pnpm demo:live`: `scripts/demo-live.ts` runs `pnpm hauntmap analyze samples/manor --out public/demo/live.json` only when `samples/manor` differs from `public/demo/manor/before` in at least one included file and `packages/hauntmap-mcp/dist/cli.js` exists; otherwise it prints `demo:live: skipped (<reason>)` and exits 0 | 120 | `kiro-integration` task 7 |

The live file is the scaffold of the spec with two entries, byte-identical to the `analyze-live.json` block of `.kiro/specs/kiro-integration/design.md`. The entry that task 7 does not observe firing is deleted (Requirement 6.2), and the file never carries an unobserved entry. The skip rule of `pnpm demo:live` (Requirement 6.8) keeps the committed `public/demo/live.json` intact: after the recorded session commits the post-edit snapshot and `pnpm demo:reset` restores the sample, every later Kiro turn prints `demo:live: skipped (samples/manor is identical to public/demo/manor/before)` and `git status --porcelain public/demo/live.json` stays empty. A checkout that has not run `pnpm build:mcp` prints `demo:live: skipped (dist/cli.js absent; run pnpm build:mcp)` instead of failing. `tests/kiro/hooks.test.ts` parses `verify-on-stop.json` and `analyze-live.json` and guards their names in the repository `README.md` and `docs/write-up.md`; `typecheck-on-save.json` follows the same rule by hand and is cited only with its own observation row. Browser journeys (`pnpm verify:e2e`) are not hooked: they run at the end of the task that needs them.

## Settled by the revision of 2026-11-16

`.kiro/steering/revision-2026-11-16.md` states that the trigger names `Stop` and `PostFileSave` and the standalone file shape (`version`, `hooks`, `name`, `trigger`, `matcher`, `action`, `timeout`) are correct for the current Kiro IDE and CLI. This README does not reopen them. An observation row records what was seen; it does not rename a trigger.

## Fields marked *verify*

JSON carries no comments, so the marks live here. Each item is confirmed on the installed Kiro CLI, the observed value goes into this list and into `docs/kiro-log.md`:

- `version: "v1"`: *verify* the schema version string.
- `matcher`: *verify* whether it is a regular expression or a glob (glob form of the save entry: `samples/manor/**/*.{js,jsx,ts,tsx,mjs,mts}`), and whether the save trigger matches a workspace-relative path with forward slashes on Windows.
- `timeout`: *verify* that the field exists and that its unit is seconds.
- `action.type: "command"` and `action.command`: *verify* that the command runs from the workspace root (where `package.json` is), and which shell runs it on Windows (PowerShell or `cmd.exe`). Every hook command is a plain `pnpm <script>`, so it runs in either.
- Two hooks on `Stop` (`verify-on-stop`, `analyze-live`): *verify* whether they run in file order, in parallel or only the first. Neither depends on the other: `pnpm verify` reads `public/demo/**`, and the live command writes only `public/demo/live.json` (through a `.tmp` file and a rename), and only when the sample differs from the fixture.
- Whether a headless session (`kiro-cli chat` with a prompt argument; flags from `kiro-cli chat --help`) runs hooks at all and prints their output. The `typecheck-on-save` row of 2026-11-16 saw no hook output in a headless session.
- Whether the Kiro IDE reads standalone `.kiro/hooks/*.json` files, or only hooks created in its own panel. An IDE observation needs a person and is optional.
- Which entry of `analyze-live.json` survives is decided by observation at `kiro-integration` task 7. The recorded session runs in the Kiro CLI, so the `Stop` entry is the expected survivor; one entry remains, never both.

## Observation before citation

A hook is cited in the repository `README.md`, the write-up, the video, the blog post, `.kiro/steering/refactoring.md` or `docs/kiro-log.md` only after it has been observed firing and the observation is logged (Requirement 6.5, enforced for the two spec hooks by `tests/kiro/hooks.test.ts`). A hook counts as observed only when its own output, or a side effect only it produces, appears in a saved transcript or file. Kiro makes every observation itself, from PowerShell, with no person at the keyboard. Procedure:

1. `pnpm verify` and `pnpm typecheck` pass from PowerShell first; a hook cannot be judged against a failing suite. Record `Measure-Command { pnpm verify }` with the machine named by `Get-CimInstance Win32_Processor` and `Win32_ComputerSystem` (CPU model, memory).
2. For the stop trigger, end a Kiro CLI turn in the repository root. For a headless session, start `kiro-cli chat` with a one-line prompt and redirect stdout and stderr to `.hauntmap/hook-<name>.txt`. For the save trigger, make a whitespace-only change to a matching file; a headless session may not raise the save trigger at all, because an agent write is not an editor save (*verify*).
3. Record whether the hook fired, the configured trigger name, the first and last lines of the command output, the duration and the shell if the output shows it. Save the excerpt as a transcript excerpt file, `docs/acceptance/hook-<name>.md`: the command that produced it and the raw output between fences.
4. Append one `docs/kiro-log.md` row per hook: the date; `Kiro CLI <version as printed>` and the model; the task cell `kiro-integration, task 2 (Setup: hook observation verify-on-stop)` for the verify hook, `kiro-integration, task 7 (Setup: hook observation analyze-live)` for the live hook and `Setup: hook observation typecheck-on-save` for the typecheck hook (no spec task); the hook file and the excerpt path; the command and its result as the hook ran it, or `not observed`; the credits the turn used, or `not shown`; `none` or the change made.
5. If no hook output reaches the saved transcript: read the hook reference of the installed CLI, change nothing that the revision fixes, try once more with any flag that the reference says enables hooks in headless mode, then record `not observed` and cite nothing.
6. Keep only observed hook files in `.kiro/hooks/` where the spec says so (task 7 deletes the unobserved `analyze-live` entry). Revert any whitespace change (`pnpm demo:reset`, `git checkout public/demo/live.json`).
7. Live snapshot (task 7, after `pnpm build:mcp`): confirm `pnpm hauntmap analyze samples/manor --out public/demo/live.json` runs from PowerShell and commit the resulting `public/demo/live.json`, the pre-edit snapshot that task 12 replaces; confirm determinism with `pnpm hauntmap analyze samples/manor --out .hauntmap/live-again.json` and `git diff --no-index --exit-code public/demo/live.json .hauntmap/live-again.json` (exit 0). Observe after a one-line edit to `samples/manor/src/notifications/receipt.ts`, record the `analyze:` line, the duration and `git diff --stat public/demo/live.json`, then end a second turn without touching `samples/manor` and confirm the `identical` skip line and that `git status --porcelain public/demo/live.json` prints nothing.

An observation in the Kiro IDE needs a person; it is optional and logged separately. It does not stand in for a CLI observation, or the reverse.

## Rules while the hooks run

- A task whose last `pnpm verify` did not pass is not finished. While the failing tests of `kiro-integration` task 1c exist, `pnpm verify` is red on purpose and the `verify-on-stop` hook fails on every stop; that is the red phase of test-first work, logged once in the task 1c row, and not a hook defect.
- A hook run that fails (non-zero exit, timeout) is a defect to log and fix, never a reason to disable the hook, to raise its timeout, to weaken `pnpm verify` or to edit the hook files to hide it. The stop hook's timeout stays 600 s.
- The 90 s figure for `pnpm verify` is a target. It is recorded with `Measure-Command { pnpm verify }` on the named machine. If the time exceeds 180 s, the hook command becomes `pnpm verify:fast`, a root script that sets `HAUNTMAP_FAST` for the child `pnpm verify` inside Node (an environment variable prefix such as `VAR=1 pnpm verify` does not run in PowerShell or `cmd.exe`); the property tests then run 50 cases instead of 200, the full suite runs before a branch is merged, and the change is logged as one decision. `tests/kiro/hooks.test.ts` accepts `pnpm verify` and `pnpm verify:fast`, and nothing else.
- If the save hook makes editing intolerable, remove it and keep the stop hook rather than loosening `pnpm typecheck`.
- The live command is `pnpm demo:live`, and `scripts/demo-live.ts` names no root but `samples/manor` and no output but `public/demo/live.json`, because that file is committed and deployed (`tests/kiro/hooks.test.ts` asserts both strings verbatim). The recorded session runs in the checkout whose `live.json` is deployed.
