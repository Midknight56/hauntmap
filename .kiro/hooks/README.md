# HauntMap hooks

Three standalone hook files in the `kiro/FORMAT.md` shape, copied to `.kiro/hooks/` in the HauntMap repository together with this README, which the `kiro-integration` spec keeps there as `.kiro/hooks/README.md` (the files table, the *verify* ledger, the observation procedure and the rules; its tasks 2 and 7 replace the *verify* marks below with the observed values). Command actions only: agent actions inject a prompt, cost credits and are not part of this package. The hooks implement "Kiro integration as a product feature" and "Fleet execution" of `plans/hauntmap-implementation-plan.md` (revision 3, 2026-11-03) and Requirement 6 of `.kiro/specs/kiro-integration/requirements.md`.

| Package file | Installed as | Entries (`name`: fires on) | Matcher | Command | Timeout | When |
| --- | --- | --- | --- | --- | --- | --- |
| `verify-on-stop.json` | `.kiro/hooks/verify-on-stop.json` | `verify-on-stop`: agent stop (CLI 3.x name `Stop`; IDE wording "on agent stop") | none | `pnpm verify`: typecheck, the Vitest unit and fixture suites and, once the integrator registers it, `pnpm pack:samples --check`; target 90 s (the rules below) | 600 | November 4 (`kiro-integration` task 2) |
| `typecheck-on-save.json` | `.kiro/hooks/typecheck-on-save.json` | `typecheck-on-save`: file save (CLI 3.x name `PostFileSave`; IDE wording "on file save") | `\.(ts|tsx)$` | `pnpm typecheck`: the typecheck step of `pnpm verify` exposed as its own root script; the integrator registers it at scaffold time (tool and flags pinned then) | 120 | November 4 |

The live file is the spec's scaffold with two entries, byte-identical to the `analyze-live.json` block of `.kiro/specs/kiro-integration/design.md`; the entry that is not observed firing by November 10 is deleted (Requirement 6.2), and the file never carries an unobserved entry. The skip rule of `pnpm demo:live` (Requirement 6.8) is what keeps the committed `public/demo/live.json` intact: after the H9 session commits the post-edit snapshot and `pnpm demo:reset` restores the sample, every later Kiro turn in any checkout prints `demo:live: skipped (samples/manor is identical to public/demo/manor/before)` and `git status --porcelain public/demo/live.json` stays empty; a worktree that has not run `pnpm build:mcp` prints `demo:live: skipped (dist/cli.js absent; run pnpm build:mcp)` instead of failing. `typecheck-on-save.json` is this package's addition: the spec's `tests/kiro/hooks.test.ts` parses the other two files and guards their names in `README.md` and `docs/write-up.md`; the typecheck hook follows the same rule by hand and is cited only with its own observation row. Browser journeys (`pnpm verify:e2e`) are not hooked: writers run them at task end and the reviewer agent runs them at gates.

## Fields marked *verify*

The shape was checked against Kiro documentation summaries on November 3, 2026, not against the installed CLI (2.37.0 until the upgrade to 3.x on November 4) or IDE 1.4.62. JSON carries no comments, so the marks live here. Confirm each item on the installed version, write the observed value into the file and record it in `docs/kiro-log.md`:

- `trigger` values `Stop` and `PostFileSave`: *verify*. `PostFileSave` is a CLI 3.x name cited in `research/rules-and-credits-check-2026-11-03.md`; `Stop` is the `kiro/FORMAT.md` example value and has no source beyond it; both are *verify*. The IDE lists its triggers as "on agent stop" and "on file save". If the installed version expects other names, change the value to the documented name of the installed version (read from its hook reference, not guessed) and log the name observed. No other trigger name (spec lifecycle, pre-tool) is used by this package.
- `version: "v1"`: *verify* the schema version string.
- `matcher`: *verify* whether it is a regular expression (as in the `kiro/FORMAT.md` example) or a glob. Glob forms of the same rules: `**/*.{ts,tsx}` for the typecheck hook, `samples/manor/**/*.{js,jsx,ts,tsx,mjs,mts}` for the save entry of the live file. The typecheck pattern has no path prefix so that `.ts` and `.tsx` files under `src/`, `packages/` and `tests/` match alike; *verify* whether the save trigger matches on a workspace-relative path (the live file's matcher assumes it).
- `timeout`: *verify* that the field exists and that its unit is seconds.
- `action.type: "command"` and `action.command`: *verify* the field names, and that the command runs from the root of the checkout the session is open in (where `package.json` is). For a Crew agent in a worktree, that worktree; *verify*.
- Two hooks on `Stop` (`verify-on-stop`, `analyze-live`): *verify* whether the installed version runs them in file order, in parallel, or only the first. Neither depends on the other; `pnpm verify` reads `public/demo/**` and the live command writes only `public/demo/live.json` (through a `.tmp` file and a rename), and only when the sample differs from the fixture.
- Whether the IDE reads standalone `.kiro/hooks/*.json` files at all, or only hooks created in its own panel: *verify*. If the panel is required on the IDE, create the same hook there and keep the JSON file as the committed record only after the panel hook is observed.
- Which surface runs the live snapshot is decided by observation at `kiro-integration` task 7 (the plan's open decision dated November 10). The H9 session is recorded in the Kiro CLI, so the `Stop` entry is the expected survivor; the `PostFileSave` entry survives only if the demo session runs in the IDE. One entry remains after November 10, never both.

## Observation before citation

A hook is cited in the repository `README.md`, the write-up, the video, the blog post, `.kiro/steering/refactoring.md` or `docs/kiro-log.md` only after it has been observed firing and the observation is logged (plan matrix row 29; Requirement 6.5, enforced for the two spec hooks by `tests/kiro/hooks.test.ts`). Procedure:

1. Scaffold first: `pnpm verify` and `pnpm typecheck` pass from a terminal on `main`, even with few tests. A hook cannot be judged against a failing suite.
2. Copy `verify-on-stop.json`, `typecheck-on-save.json` and this README into the repository's `.kiro/hooks/`. Do not install the live file yet: it is observed at task 7, and until `pnpm build:mcp` has run `pnpm demo:live` only prints its skip line.
3. In a Kiro CLI 3.x session opened at the repository root (the surface the Crew pilot uses): save a `.ts` file under `src/contracts/` with a whitespace-only change; then ask the agent for a one-line answer and let the turn end.
4. For each hook, record whether it fired, the configured trigger name, the first and last lines of the command output, the duration, and a screenshot of the hook output saved as `docs/acceptance/img/2026-11-04-hook-stop.png` or `docs/acceptance/img/2026-11-04-hook-save.png`.
5. Append one `docs/kiro-log.md` row per hook: the date; `Kiro CLI <version string as printed>` and the model shown in the session; the task cell `kiro-integration, task 2 (Setup: hook observation verify-on-stop)` for the verify hook and `Setup: hook observation typecheck-on-save` for the typecheck hook (no spec task); the hook file and screenshot path; the command and its result as the hook ran it; the credits the turn used; `none` under "what changed because of a failure", or the change made (for example a corrected trigger name).
6. If a hook does not fire: read the trigger names in the installed CLI's hook reference, change the value, repeat steps 3–5 once, and log both attempts. If the IDE will also be a working surface, repeat the observation in the IDE (1.4.62 or updated once) and log it separately; an IDE observation does not stand in for the CLI one, or the reverse.
7. Keep only observed hook files in `.kiro/hooks/`; delete an unobserved one rather than keeping it as decoration. Revert the whitespace change.
8. Live snapshot (`kiro-integration` task 7, November 9–10, after task 6 has built the package): copy `analyze-live.json` to `.kiro/hooks/analyze-live.json`; confirm `pnpm hauntmap analyze samples/manor --out public/demo/live.json` runs from a terminal and commit the resulting `public/demo/live.json` (the pre-edit snapshot; task 12 replaces it with the session's file); confirm the determinism of the CLI by running `pnpm hauntmap analyze samples/manor --out .hauntmap/live-again.json` and `cmp public/demo/live.json .hauntmap/live-again.json` (prints nothing; a difference is a defect for `analysis-core`). Observe on the surface chosen for the demo after a one-line edit to `samples/manor/src/notifications/receipt.ts` (a whitespace-only change is enough, since the sample then differs from the fixture): in the CLI, end a turn (the `Stop` entry); in the IDE, save the file (the `PostFileSave` entry). Record whether each entry fired, the `analyze:` line the CLI printed through `pnpm demo:live`, the duration, `git diff --stat public/demo/live.json`, the screenshot `docs/acceptance/img/2026-11-10-hook-analyze-live.png` and the trigger name accepted; delete the entry that was not observed; revert with `pnpm demo:reset` and `git checkout public/demo/live.json`; append the row `kiro-integration, task 7 (Setup: hook observation analyze-live)`. Then end a second turn without touching `samples/manor` and confirm that the hook printed `demo:live: skipped (samples/manor is identical to public/demo/manor/before)` and that `git status --porcelain public/demo/live.json` prints nothing (Requirement 6.8).

Rules while the hooks run: a task whose last `pnpm verify` did not pass is not finished; a hook run that fails (non-zero exit, timeout) is a defect to log and fix, never a reason to disable the hook, to raise its timeout, to weaken `pnpm verify` or to edit `.kiro/hooks/**` (owned by the `kiro-integration` session per `steering/ownership.md`); the stop hook's timeout stays 600 s and the 90 s figure for `pnpm verify` is a target recorded in the H4 and H5 package rows of `docs/kiro-log.md` (`time pnpm verify` on the named laptop); if that time exceeds 180 s, the hook command becomes `HAUNTMAP_FAST=1 pnpm verify` (the property tests then run 50 cases instead of 200; `tests/kiro/hooks.test.ts` accepts exactly that string as the alternative) and the full 200-run suite runs at gates and in the integrator's merge check, logged as one decision; if the save hook makes editing intolerable, remove it and keep the stop hook rather than loosening `pnpm typecheck`; the live command is `pnpm demo:live` and `scripts/demo-live.ts` names no root but `samples/manor` and no output but `public/demo/live.json`, because that file is committed and deployed (`tests/kiro/hooks.test.ts` asserts both strings verbatim); the H9 recording runs in the checkout whose `live.json` is deployed (the main checkout, or the `kiro-integration` worktree merged before the release build).
