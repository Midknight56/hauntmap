# Analysis rules

Rules for `src/analysis/**`, `src/contracts/**`, `src/workers/**`, `tests/fixtures/**`, `public/demo/**`, `samples/**` and `packages/hauntmap-mcp/**`. They implement "Parser and resolver scope", "Main contracts" and "Analysis rules" of `plans/hauntmap-implementation-plan.md` (revision 3, 2026-11-03). One analysis module serves the app, the worker, the MCP server and the CLI: `tests/analysis-boundary.test.ts` fails if any file under `src/analysis` or `src/contracts` imports from `src/scene`, `src/features`, `src/components` or a DOM API.

## Supported subset (the resolver is not TypeScript, Node or a bundler; never claim identical resolution)
- Parse `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.mts` with Babel's parser in the explicit mode for each extension (version pinned at scaffold time; read the import/export kind fields of that version, *verify* their names).
- Extract static import declarations, side-effect imports, `export … from` and `export * from`. Literal `import("…")` is `syntaxKind: "dynamic-literal"`, `dependencyKind: "value"`, added only after static extraction passes its fixtures.
- Classify syntax and dependency kinds independently: `export type { Foo } from "./x"` is `re-export` + `type`; `import { formatMoney, type Money } from "../shared/money"` is `import` + `mixed`; side-effect imports and `export * from` are `value`; `export type * from` is `type`. A declaration with both value and type specifiers is `mixed`, never `type`.
- Resolve relative specifiers inside the selected root only: the exact file first; then `.ts`, `.tsx`, `.mts`, `.js`, `.jsx`, `.mjs`; then `index.ts`, `index.tsx`, `index.js`, `index.jsx` in the directory. Map `./x.js` to `x.ts` or `x.tsx` and `./x.mjs` to `x.mts` only when the exact file is absent, and record `jsToTsFallback: true` in `AnalysisOptions`. Two candidates that differ only in case yield reason `ambiguous-candidate`.
- Classify a bare specifier that is a valid npm package name (optionally scoped, optional subpath) as `external`. Never install, read or analyze `node_modules`. A bare specifier that is not a valid package name (`@/lib/format`, `~/config/env`) is `unresolved` with reason `alias-not-configured`.
- Treat tsconfig `paths` and `extends`, package `exports` conditions, CommonJS `require`, non-literal dynamic imports, Vue and Svelte files and build-plugin transforms as out of scope: record `unsupported` with a reason and a location where the construct is recognizable; never guess a target.
- Never execute, import, evaluate or fetch analyzed source: no npm scripts of the analyzed project, no `eval`, no rendering of its HTML as active content, no requests for its remote imports.

## No fabricated edges or facts
- An absent relative target is `unresolved` with reason `absent-file`; an external package never becomes a local room; a parse failure produces `parseStatus: "failed"`, a `parse-failed` diagnostic and leaves every other module intact. Coverage is reported incomplete, never padded.
- Keep every unresolved, ambiguous or unsupported edge in `diagnostics` with its module, line, column and specifier (codes: `parse-failed`, `unresolved`, `unsupported`, `case-collision`, `duplicate-path`, `oversized`, `cap-reached`).
- `expected.json` for `manor/before`, `manor/after`, `annex` and every unit fixture is authored by hand from the source files (the manor pair and its `expected.json` by the fleet scaffold agent on November 4, the rest by the `fixtures` agent). Never generate or "refresh" expected facts with the analyzer under test, and never edit a fixture's source to make a failing assertion pass.
- Manor facts the tests rely on: 40 modules; under `static-value` exactly one cyclic component with members `src/notifications/receipt.ts`, `src/orders/checkout.ts`, `src/payments/charge.ts`; one external import; one absent file; one type-only re-export cycle visible only under `type-inclusive`; one mixed import; one dynamic literal. `manor/after` differs by exactly one removed relation (`src/notifications/receipt.ts → src/orders/checkout.ts`), one added relation (`receipt.ts → src/orders/summary.ts`) and `changedModules` `["src/notifications/receipt.ts", "src/orders/checkout.ts"]` (the second changed only by an inserted comment); one cyclic component before, none after. Annex: three disjoint cyclic components of sizes 2, 3 and a self-loop; two `alias-not-configured` imports (`@/lib/format`, `~/config/env`).

## Identifiers
- Module ID: the path relative to the root with forward slashes and no leading `./`. Raise `case-collision` when two paths differ only in case and `duplicate-path` when two inputs normalize to one path.
- `sourceHash`: SHA-256 hex of the UTF-8 text (Web Crypto in the app, `node:crypto` in the CLI and the server).
- `occurrenceId` = `JSON.stringify([from, line, column, specifier])`; `relationId` = `JSON.stringify([from, targetKey, syntaxKind, dependencyKind])` with `targetKey` = `["local", to]` for a resolved local edge and `[resolution, specifier]` for an external, unresolved or unsupported boundary. Never build an ID by delimiter concatenation. Line and column are shown one-based in the UI.
- Compare snapshots and select doors by relation ID; navigate to source by occurrence ID; select rooms by module ID. Several occurrences may share one relation ID: removing one of two identical imports changes the evidence count, not the relation; moving an import by one line changes the occurrence ID and the hash, never the relation ID.
- Source text never enters an `Investigation`, an export, `public/demo/live.json` or an MCP response; it lives in a separate in-memory map. `schemaVersion` is `1` and `resolverMode` is `"documented-source-subset"`; a reader rejects anything else with the path and the validation error.

## Presets and algorithms
- `static-value` (default): `import` and `re-export` syntax with `value` or `mixed` kind. `type-inclusive` adds `type` relations. `dynamic-inclusive` adds `dynamic-literal` syntax. A `mixed` relation is traversed once. A type-only re-export never closes a cycle under `static-value`.
- Compute strongly connected components over the preset's resolved local edges. A size-one component is cyclic only with a self-edge. Produce exactly one witness per component by deterministic node ordering, starting at the lexically smallest member; never enumerate all simple cycles.
- Reverse breadth-first search from the chosen module gives `direct` (one relation away), `indirect`, `predecessor` and `distance`; the shortest witness path comes from `predecessor`. Both algorithms stay linear in vertices plus edges.
- Sort every set-valued list (component members, `direct`, `indirect`, added, removed and changed modules, relations by relation ID, diagnostics); keep walks (witness, path) in walk order. Results must be byte-identical across runs and across the app, the CLI and the server. Put the active preset in every `CycleReport`, `TraceResult`, export and MCP response; `ComparisonResult` counts cycles under `static-value`.
- Apply `AnalysisOptions` identically in the browser loader and the Node loader: the six extensions; excluded directories `.git`, `node_modules`, `dist`, `build`, `out`, `.next`, `coverage`; excluded patterns `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`; 1,000 files locally or 400 from GitHub; 1 MiB per file; 25 MiB in total. Above a cap, stop with `cap-reached` naming the count and the first excluded path. The same folder yields identical module IDs, hashes and relation IDs by every route (matrix row 26).

## Workers
- Every message carries `{ requestId, revision, kind, payload }`; discard any result whose revision is older than `currentRevision`. Cancel or supersede by calling `terminate()` and creating a fresh worker (a message cannot interrupt synchronous parsing or layout); the last completed investigation stays in UI state and a failed job leaves it intact. Test cancellation during computation, not only between files.
